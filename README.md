# PH908 Reproducible Analysis Pipeline

Reproducible R pipeline for the manuscript:

**“I2a-PH908 branch structure supports a western-Balkan reservoir rather than a simple Slavic-period recipient model”**

This repository contains the deterministic preprocessing workflow, six analytical pillars, figure and table rendering scripts, and publication-oriented outputs used to reproduce the manuscript results from curated branch-level input data. The analytical design compares PH908 against a matched R1a control under identical preprocessing, branch-construction, and downstream inference rules.

## Repository contents

### Core scripts

* `config_analysis.R` — central paths, constants, and shared configuration
* `run_all.R` — master runner for the full pipeline
* `01_preprocessing.R` — deterministic source-table preprocessing and branch annotation
* `02_pillar1_burden.R` — burden-capacity analysis
* `03_pillar2_topology.R` — cross-region branch-link topology analysis
* `04_pillar3_anchor.R` — anchor-packet occupancy analysis
* `05_pillar4_concentration.R` — relic concentration analysis
* `06_pillar5_depth.R` — depth-structured coherence analysis
* `07_pillar6_sourcesink.R` — deep-core source–sink inversion analysis
* `08_presentation.R` — figure and supplementary table rendering
* `plot_style.R` — shared publication plotting style

### Input files

* `dnk_source_snapshot.csv` — source snapshot retained for provenance
* `dnk_source_table.csv` — cleaned source table consumed by preprocessing
* `branch_ages.csv` — curated terminal-branch age table
* `geocoded_locations_cache.rds` — reviewed geocoding cache
* `ph908_branch_map.tsv` — PH908 branch annotation map
* `ph908_node_age_tiers.tsv` — PH908 node-age tier definitions

## How to run

For a full clean rerun:

1. Keep all source files and scripts in the project root.
2. Empty previously generated outputs from:

   * `results/`
   * `facts/`
   * `figuredata/`
   * `tables/`
   * `figures/`
   * generated preview subfolders inside `supplement/`
3. Run the master script from the project root:

```r
source("run_all.R")
```

The runner executes the pipeline in this order:

1. preprocessing
2. Pillar 1 burden-capacity bound
3. Pillar 2 topology
4. Pillar 3 anchor-packet occupancy
5. Pillar 4 concentration
6. Pillar 5 depth coherence
7. Pillar 6 source-sink inversion
8. presentation and supplementary rendering

For the final manuscript-grade rerun, the recommended `run_all.R` settings are:

```r
CONTINUE_ON_ERROR <- FALSE
STRICT_OUTPUT_CHECKS <- TRUE
```

## Logs and audit trail

`run_all.R` writes timestamped run artifacts into `logs/`, including:

* a full pipeline log
* a run summary CSV
* a warnings file

These files provide an execution audit trail for the clean rerun.

## Analytical structure

The six analytical pillars evaluate:

1. demographic burden under strict exogenous assumptions
2. cross-region branch-link topology
3. retention within a PH908-defined relic anchor packet
4. regional concentration in balanced shared-region arenas
5. depth-structured regional coherence under age-aware reconstruction rules
6. deep-core source-sink behavior

## Reproducibility notes

* Preprocessing is deterministic.
* Branch mass is measured conservatively as cluster count rather than raw member count.
* PH908 and R1a are processed under the same filtering, clustering, branch-definition, and comparative framework.
* Script-generated facts files are intended to support final consistency checks against the manuscript and supplement.
